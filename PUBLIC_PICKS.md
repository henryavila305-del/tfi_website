# Public picks preparation

The public board remains empty. content/public-picks.json must contain [] until the owner separately authorizes public publication and the required evidence controls are implemented. The current validator deliberately blocks nonempty lists. Static rendering is implemented, but production builds deliberately reject nonempty lists. No feed is connected.

Each future public entry requires exactly: id (unique lowercase slug), sport (NFL/NBA/MLB/NHL/NCAAF/NCAAB), selection, market, odds (integer American odds), publishedAt and eventAt (canonical UTC ISO timestamps ending .000Z), reasoning, result (pending/win/loss/push/void), publicApproved (true), and approvalReference (a public-safe approval identifier). Publication must precede the event. The owner has confirmed pre-event-only posting, UTC publication times and no backdating (PUBLIC-PICK-TIMING-01). publishedAt must be the actual first public release; approval time, analysis time or private-message time is not a substitute. Existing validation checks the supplied dates, not proof of a real publication event. Trusted first-publication evidence must be implemented before real entries can be enabled; the empty-content hold remains enforced.

All repository content is public, including test fixtures and commit history. Never put drafts, member picks, private approval conversations, credentials, workbook rows or source identifiers here. Only already-cleared public entries may ever be committed. Unknown fields fail validation; this is structural validation, not an automated privacy guarantee.

The owner has confirmed the per-pick rule (PUBLIC-PICK-APPROVAL-01): every individual public pick requires the owner's individual approval before appearing; private/member picks are excluded. Each future approvalReference must refer to that pick's genuine owner approval using a public-safe identifier. The validator checks structure and cannot authenticate who approved a pick. A blanket policy approval is not an entry approval. Existing approved aggregate history is unaffected.

The owner-selected sources are DraftKings for recorded odds and ESPN for final-result reference (PUBLIC-PICK-SOURCES-01). No provider feed, credentials or source capture is connected. The current entry schema does not yet store source evidence; define and implement the capture/evidence contract before enabling real entries. The owner also confirmed capture at first public posting, preserving the original DraftKings price and recording later corrections separately (PUBLIC-PICK-PRICE-01). Ordinary price movement must not overwrite the original. This requires source-capture and correction-history implementation before enabling entries; the current plain odds field alone does not provide that audit trail. This does not change previously imported historical aggregates.

The owner approved individual approval before posting each grade; win percentage calculated as wins / (wins + losses), excluding pushes and voids; postponed games remaining pending until the owner approves a final outcome; and visible grading corrections (PUBLIC-PICK-GRADING-01). This policy approval does not approve an individual grade or alter imported historical aggregates. Implement grade-approval evidence and visible correction history before enabling entries.

Before enabling entries, implement actual-first-publication evidence for the approved timing rule and define the approval-record process; obtain market/location context, source-evidence details, withdrawal procedures and approved public explanations. Approval references must not contain private URLs or messages.

The build renders validated public entries into a dedicated HTML slot, escaping text and retaining native headings, descriptions and UTC time elements without JavaScript. The empty array preserves the reviewed empty state byte for byte. Approval metadata is never rendered. Synthetic tests and ignored local fixtures cover populated output without changing production content and prove that a direct build rejects nonempty content. Next phase: define and implement evidence for approved grading and visible correction history while retaining both holds. Do not connect a tracker or database.

Run npm run check and npm run build:check. The static output remains the existing five assets; content files and validation fixtures are not shipped. vercel.json disables Git-triggered deployments on this branch. No deployment, DNS, account, or billing action is included.
